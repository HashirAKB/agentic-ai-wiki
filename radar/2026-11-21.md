# Tools radar: 2026-11-21

Scan window: roughly 2026-11-07 to 2026-11-21. Items already in `seen.md` or `playbooks/README.md` are not repeated.

## Top picks

### 1. External sandboxes for coding agents ([Willison](https://simonwillison.net/2026/Nov/17/external-sandboxes-for-coding-agents/)) — Workflow tip / CLI/tool — from: Simon Willison, repos by prime-radiant-inc
- **What it does:** A pattern where code the agent runs executes in a separate sandbox (WASM Alpine, Apple Containers, or QEMU) behind a localhost API, while the agent stays outside. Optional allow-list HTTP proxy and credential substitution.
- **Why it's useful:** Contains prompt-injection or mistakes away from your host, and the credential replacement means the agent never holds real secrets. Good fit with the Rule of Two material already in this wiki.
- **How to try:** Clone one of [external-sandbox-v86](https://github.com/prime-radiant-inc/external-sandbox-v86), [external-sandbox-container](https://github.com/prime-radiant-inc/external-sandbox-container) or [external-sandbox-quicksand](https://github.com/prime-radiant-inc/external-sandbox-quicksand), start the server, and follow its README to point your agent at it. The post has no setup steps.
- **Risks:** Young, unofficial repos. The sandbox is only as safe as its proxy policy; a permissive allow-list restores exfiltration paths. Apple Containers variant is macOS only.
- **First exercise:** Start the v86 variant (any OS with Node), run a trivial script that fetches a URL, and confirm the proxy UI shows the request, then block the host and confirm it fails.
- **Verdict:** Try now.

### 2. Claude Fable 5.2 (`claude-fable-5-2`) ([announcement](https://www.anthropic.com/claude-fable-and-mythos-5-2)) — Anthropic feature — from: Anthropic
- **What it does:** New top model (1M context, 128k output, adaptive thinking), $8/$40 per MTok, fast mode at $16/$80. Mythos 5.2 is the same model restricted to verified cyber and life-science orgs. Anthropic suggests starting on Opus 5.5 and escalating to Fable for hard work, or using Fable as Advisor or Orchestrator.
- **Why it's useful:** Stronger on hard coding and long-horizon tasks; the Advisor pattern lets a cheaper executor consult it only when stuck.
- **How to try:** In Claude Code run `/model` and pick Fable 5.2 (plan usage is capped at about 50% of weekly limits on Pro and standard Team seats). API: model ID `claude-fable-5-2`.
- **Risks:** Requires 30-day data retention (no zero data retention). Costs more than Opus 5.5. API change: sending back thinking blocks after editing earlier prompt content now returns 400.
- **First exercise:** Give Opus 5.5 and Fable 5.2 the same hard bug in a small repo; compare the fix and token use in `/cost`.
- **Verdict:** Try now.

### 3. Code Mode with easel charts and `/tasks` (Claude Code 2.1.326–2.1.330) ([changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)) — Anthropic feature — from: Anthropic
- **What it does:** 2.1.330 adds easel, a built-in mod that draws charts, including under MCP metrics results. 2.1.329 puts scheduled tasks, `/loop` wakeups and forks in `/tasks`. 2.1.327 adds `claude mcp add-json <name> -` to read server JSON from stdin, and a `/status` list of broken skills, hooks and settings.
- **Why it's useful:** Keeps tokens out of shell history, shows config problems in one place, and gives a single view of background work.
- **How to try:** Update Claude Code, then run `/status` and `/tasks`. Charts toggle in `/config`.
- **Risks:** Low. easel is built in; it can be blocked by MCP allow or deny lists.
- **First exercise:** Run `/status` on a real project and fix one reported item; add an MCP server with `echo '{...}' | claude mcp add-json demo -`, then confirm it in `/mcp`.
- **Verdict:** Try now.

### 5. Linked billing (beta) ([release notes](https://platform.claude.com/docs/en/release-notes/overview)) — Anthropic feature — from: Anthropic
- **What it does:** Customers pay for Claude usage in your app through their own Claude organization (`user-profiles-billing-2026-10-01` header, `billing_policy` on requests).
- **Why it's useful:** Lets an app you build avoid carrying its users' inference cost.
- **How to try:** Add the beta header and set `billing_policy` on `/v1/messages` in a test app.
- **Risks:** Beta; only for customers whose org pays Anthropic directly.
- **First exercise:** Send one request with `billing_policy` set and confirm the response is accepted.
- **Verdict:** Watch.

### 6. Compliance API security posture and IP allowlist (beta) ([release notes](https://platform.claude.com/docs/en/release-notes/overview)) — Anthropic feature — from: Anthropic
- **What it does:** Enterprise-only security posture endpoint, IP allowlists (up to 1,000 ranges), and sign-out-everywhere via the Admin API.
- **Why it's useful:** Relevant only if you administer a Claude Enterprise org.
- **How to try:** Enterprise admin console and Admin API.
- **Risks:** An allowlist mistake can lock out your own requests.
- **First exercise:** None for an individual developer.
- **Verdict:** Skip-for-now.

### 7. Claude Code `onFailure: block` for `mcp_tool` hooks and auto mode on Bedrock/Vertex/Foundry (2.1.328) ([changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)) — Anthropic feature — from: Anthropic
- **What it does:** A hook whose MCP call fails now blocks the action (fail closed). Auto mode extends to Opus 4.6 and Sonnet 4.6 on third-party clouds.
- **Why it's useful:** Safety hooks that fail open give false confidence.
- **How to try:** Set `"onFailure": "block"` on an `mcp_tool` hook in settings.
- **Risks:** A flaky hook server will now stop your work.
- **First exercise:** Point a hook at a dead server and confirm the action is blocked.
- **Verdict:** Watch.
